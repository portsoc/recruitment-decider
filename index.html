    How a suspension request is weighed

    These thresholds tune how the tool judges whether a suspension request is justified. Calibrate them against real outcomes over time.

    These settings and key dates are shared by everyone using the tool. Only the ADS can change them.

    Over-enrolment is a concern. Probability is measured against cap × (1 + buffer), not the cap itself.

    This is separate from expected withdrawals. The forecast already takes off each course's typical withdrawals before it is compared with the cap, so a course can enrol above cap by its expected withdrawals without triggering a recommendation. The buffer is extra headroom on top of that. Set it to 0 if going over cap by expected withdrawals is all that should be allowed.

    (e.g. 0.05 = 5% above cap)

    Minimum P(overshoot) at which the tool recommends submitting the request.

    (e.g. 0.70 = 70%)

    Between this and the submit threshold, the tool flags the situation as borderline.

    (e.g. 0.40 = 40%)

    Inside this window before start, the tool will recommend against asking — too late for suspension to be meaningful.

    weeks

    How much extra forecast spread is applied when little of the application curve has played out yet. Higher = more sceptical of early-cycle predictions.

    (default 1.5)

    Below this fraction of the application curve, the recommendation is discounted proportionally. Stops the tool from confidently recommending a suspension on flimsy early-cycle data.

    (default 0.40 = 40%)
